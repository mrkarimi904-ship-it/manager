Connect to Manager

The Manager service (this repo: vms_manager) is a NestJS API. In the current config, it runs with a global prefix of /manager.

Base URL

Use your deployment host, plus the Manager prefix. Typical local dev: http://localhost:3004/manager

Health checks

Method Path (with prefix) Description
GET /health Basic service health.
GET /health/status Health status details. 
# Local example (prefix = /manager)
curl -sS "http://localhost:3004/manager/health"
curl -sS "http://localhost:3004/manager/health/status"

Swagger UI

Swagger UI is served at the server root (relative to the prefix). In most deployments it ends up at: http(s)://HOST/manager/ (or a reverse-proxy equivalent).

Authentication

Most endpoints require a JWT in the Authorization header: 

Authorization: Bearer <JWT_TOKEN>
Important

Login itself does not require a token. After login, include the bearer token for protected routes like /lpr_results.

Login / Logout / Verify

Login

POST /user/access/login

Returns a JWT plus a user id and a list of claims (roles). Token lifetime depends on service and whether the user is a super admin.

Field Type Required Notes
username string Yes Case-insensitive; server normalizes to lowercase.
password string Yes Minimum length is enforced server-side.
service string No Controls token expiration. Supported values: Configtool, Client, otherwise treated as Other.
ip string No Used by scheduler rules (if enabled). If behind a proxy, server may use x-forwarded-for.
mac string No Used by scheduler rules (if enabled).
totp string No* Required only if the account has TOTP enabled; otherwise optional. 
curl -sS -X POST "http://localhost:3004/manager/user/access/login" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin",
    "password": "admin1234",
    "service": "Client",
    "ip": "192.168.1.10",
    "mac": "AA:BB:CC:DD:EE:FF",
    "totp": ""
  }'
const baseUrl = "http://localhost:3004/manager";

async function login({ username, password }) {
  const res = await fetch(`${baseUrl}/user/access/login`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      username,
      password,
      service: "Client",
      ip: "192.168.1.10",
      mac: "AA:BB:CC:DD:EE:FF",
      totp: ""
    })
  });

  if (!res.ok) throw new Error(`Login failed: ${res.status}`);
  const json = await res.json();
  if (!json?.status) throw new Error(`Login error: ${JSON.stringify(json)}`);

  // json.data: { token, id, claims }
  return json.data;
}
Login response shape 
{
  "status": true,
  "data": {
    "token": "<JWT>",
    "id": "<user_uuid>",
    "claims": [ /* role objects */ ]
  },
  "error": null,
  "msg": null
}

Verify token

GET /user/access/verify — checks the bearer token and echoes identity data; also returns X-User_ID header. 

TOKEN="<JWT_TOKEN>"
curl -i -sS "http://localhost:3004/manager/user/access/verify" \
  -H "Authorization: Bearer ${TOKEN}"

Logout

POST /user/access/logout — revokes the current token (deletes it server-side). 

TOKEN="<JWT_TOKEN>"
curl -sS -X POST "http://localhost:3004/manager/user/access/logout" \
  -H "Authorization: Bearer ${TOKEN}"

LPR Results Search

GET /lpr_results — paginated search over LPR detections.

What does “search” match?

search is applied to the ocr field using a case-insensitive “contains” match (similar to SQL ILIKE %value%).

Query parameters

Param Type Default Meaning
pageIndex string (int) 1 1-based page number.
pageSize string (int) 20 Page size (server caps to max 100).
search string "" OCR/plate search (contains, case-insensitive).
brand string "" Vehicle brand filter (contains, case-insensitive).
model string "" Vehicle model filter (contains, case-insensitive).
type string "" Vehicle type filter (contains, case-insensitive).
color string "" Vehicle color filter (contains, case-insensitive).
plateType string "Car" Plate type filter (contains, case-insensitive).
address string "" Camera address filter (contains, case-insensitive).
isBlackList string ("true"/"false") — Filter on black-list matches.
isWhiteList string ("true"/"false") — Filter on white-list matches.
isNotifable string ("true"/"false") — Filter on notification flag.
dateFrom ISO-8601 string — Include records with created_at >= dateFrom.
dateTo ISO-8601 string — Include records with created_at <= dateTo.
cameraIds string — Comma-separated camera UUIDs. Server will reject IDs not permitted for the user.

Example: search by OCR + brand + date range

TOKEN="<JWT_TOKEN>"

curl -sS "http://localhost:3004/manager/lpr_results?pageIndex=1&pageSize=20&search=IR12&brand=Toyota&dateFrom=2026-04-01T00:00:00.000Z&dateTo=2026-04-20T23:59:59.999Z" \
  -H "Authorization: Bearer ${TOKEN}"

Example: multi-camera filter

TOKEN="<JWT_TOKEN>"
CAMERA_IDS="uuid1,uuid2,uuid3"

curl -sS "http://localhost:3004/manager/lpr_results?cameraIds=${CAMERA_IDS}&pageIndex=1&pageSize=50" \
  -H "Authorization: Bearer ${TOKEN}"

Response shape

The API wraps results in the standard response envelope. For searches, data is: { total, result }, where result is an array of LPR rows (includes lpr_result_image). 

{
  "status": true,
  "data": {
    "total": 1234,
    "result": [
      {
        "id": "…",
        "ocr": "IR12ABC345",
        "vehiclebrand": "Toyota",
        "vehiclemodel": "Corolla",
        "vehicletype": "Sedan",
        "vehiclecolor": "White",
        "created_at": "2026-04-20T12:34:56.789Z",
        "isBlackList": false,
        "isWhiteList": false,
        "isNotifable": false,
        "lpr_result_image": [
          {
            "plateimage": "…base64…",
            "vehicleimage": "…base64…",
            "frame": "…base64…",
            "generatedplateimage": "…base64…"
          }
        ]
      }
    ]
  },
  "error": null,
  "msg": null
}
Images (MinIO vs DB)

If your deployment uses MinIO, image fields may be stored outside the database; the API attempts to fetch and convert them to base64 in responses.

LPR Result Details

GET /lpr_results/details/:id — get a single LPR result by id (UUID). 

TOKEN="<JWT_TOKEN>"
ID="<lpr_result_uuid>"

curl -sS "http://localhost:3004/manager/lpr_results/details/${ID}" \
  -H "Authorization: Bearer ${TOKEN}"

Update editable fields

PUT /lpr_results/details/:id — updates OCR/brand/model/type/color fields for an LPR result.

Field Type Maps to DB field
platestringocr
brandstringvehiclebrand
modelstringvehiclemodel
typestringvehicletype
colorstringvehiclecolor
 
TOKEN="<JWT_TOKEN>"
ID="<lpr_result_uuid>"

curl -sS -X PUT "http://localhost:3004/manager/lpr_results/details/${ID}" \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "plate": "IR12ABC345",
    "brand": "Toyota",
    "model": "Corolla",
    "type": "Sedan",
    "color": "White"
  }'

Errors & status codes

Errors are returned as JSON in the same envelope shape; HTTP codes vary by endpoint.

HTTP When Common causes
401 Unauthorized Missing/invalid token, revoked token, bad username/password, missing TOTP when required.
403 Forbidden User lacks required role/claim for the route.
406 Not acceptable Validation errors or logical errors (e.g., camera not permitted for the user). 
{
  "status": false,
  "data": null,
  "error": { "message": "…" },
  "msg": "…"
}
